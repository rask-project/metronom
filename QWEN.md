# Metronom (Rask Metronom)

Metronome application in **Qt 6 / QML** (Qt Quick + Material style).

## Structure

- `CMakeLists.txt` — CMake build, QML module `Metronom` (URI `Metronom`), executable target `metronom`.
- `main.cpp` — `QGuiApplication` + `QQmlApplicationEngine`, loads `Metronom.Main`.
- `Main.qml` — root `ApplicationWindow` (640×480, min. 200×250, Material).
- `build/` — out-of-source build directory (gitignored), generated by Qt Creator.
- `.qtcreator/` — local Qt Creator configuration (gitignored).

| Aspect | Detail |
|---|---|
| **Language** | C++23 |
| **Framework** | Qt 6.11 (Quick / QML) |
| **Build** | CMake + Ninja |
| **Code style** | clang-format-18 (LLVM-based), 120 columns, 4 spaces, never tabs |

## Build and run

Kit: Qt 6.11.2 (`/opt/Qt/6.11.2/gcc_64`), CMake ≥ 3.16, Ninja, g++ via ccache, Debug preset.

```sh
# Configure (if build/ doesn't exist yet)
cmake -B build/Desktop_Qt_6_11_2_Debug -G Ninja \
  -DCMAKE_PREFIX_PATH=/opt/Qt/6.11.2/gcc_64 -DCMAKE_BUILD_TYPE=Debug

# Build
cmake --build build/Desktop_Qt_6_11_2_Debug

# Run
./build/Desktop_Qt_6_11_2_Debug/metronom
```

Qt Creator also opens the project directly with the "Desktop Qt 6.11.2 Debug" kit.

## Conventions

- **Language:** respond in Portuguese.
- **Comments:** minimal — names speak for themselves; at most one short line when the "why" is not obvious.
- **Build:** only compile when the user explicitly asks; don't run a build on your own to "validate" changes.
- **Work order:** get the code compiling/working first; review tests later.
- **Intentionally commented-out code** for testing parts in isolation is not a bug — confirm it's intentional before "fixing" it.
- **Hot paths (byte parsing/conversion):** zero allocation, raw reading with shifts/bitwise; avoid `QDataStream`, `QByteArray::fromHex` and unnecessary abstractions.
- **Design:** minimal solutions, no speculative fields/columns.

**C++**

- C++23 or newer (C17 only where C code is genuinely required).
- Pointer: only unique_ptr. Never use raw or shared_ptr.
- Early-return over nesting. Avoid deep or complex `if`/`else` chains — flatten with guard clauses.
- Prefer `std::ranges` algorithms over hand-written loops and conditionals.
- Honour `.clang-tidy`; warnings are errors.
- Performance: `emplace_back` over `push_back`, move over copy, no needless temporaries.
- Memory safety through RAII — no raw `new`/`delete`, no leaks. Mark `noexcept` where it holds.
- Minimal comments — only where the code cannot explain itself, and always in English.

**Qt / QML**

- Follow Qt idioms: signals/slots, `Q_PROPERTY`, and Qt's model classes for list data.
- QML stays declarative. Business logic belongs in C++ — a QML file that grows imperative logic is a bug in the layering, not a style preference.
- Check <https://doc.qt.io> for component and API behaviour rather than guessing.
- QML best practices <https://doc.qt.io/qt-6/qtquick-bestpractices.html>
- QML code conventions <https://doc.qt.io/qt-6/qml-codingconventions.html>
